# 产品需求

本文只记录访谈中已经确认的产品需求；未决事项在确认后再加入。

## 已确认需求

- 产品以本地透明反向代理的形式接收请求，并由同一进程中的 TUI 管理；退出 TUI 即停止代理。
- 路由和可用状态绑定到上游凭证。第一版不识别多个 Key 背后的共享账号或额度。
- 路由池只包含请求表面兼容的上游凭证。同一路由池可以透传多种协议，但同一原始请求必须能直接发送给池内任一凭证；路由器不做协议转换或模型映射。
- 只有响应明确命中服务的额度规则时，才将上游凭证标记为额度不足。瞬时限速、认证失败、超时和服务故障必须区别处理。
- 用户可以手动切换当前上游凭证，也可以手动将上游凭证标记为额度不足。
- 日志必须能够还原凭证选择、响应分类、切换重试和额度验证的决策链。默认不得记录 API Key、认证头或请求正文。

### 日志策略

- 默认使用 `info` 级别的结构化 JSONL 文件，并支持在 TUI 中实时查看。
- 日志按单文件 `10 MiB` 轮转并保留五个文件。
- 每个请求记录关联 ID、路由池、凭证脱敏指纹、方法与路径、上游状态码、耗时、响应分类、状态变化和重试过程。
- `debug` 级别可以额外记录经过敏感字段清理的响应头，以及最多 `4 KiB` 的上游错误响应体。
- 任何日志级别都不得记录成功请求体、成功响应体、认证头或完整 API Key。

## 服务配置

- 服务配置与上游凭证分离，并可被多个凭证复用。
- 产品同时提供常用服务的内置预设和用户自定义服务配置。
- 服务配置包含默认服务地址、认证头及前缀、验证请求模板，以及成功、额度不足和认证失败的响应规则。
- 上游凭证引用一个服务配置，并包含自身的 API Key 和可选的服务地址覆盖。
- 第一版内置 OpenCode Go、OpenCode Zen、OpenAI-compatible 和 Anthropic-compatible 服务预设，并始终提供自定义 HTTP 配置。
- 第一版不内置 Gemini、Bedrock、Azure 等认证方式明显不同的服务。
- 第一版假设同一 API Key 的额度对所有模型共享，凭证状态适用于该凭证承接的全部请求；不建模模型级或时间窗口级额度状态。

### 响应规则

- 自定义服务使用有序结构化规则对上游响应分类，第一个匹配的规则生效。
- 单条规则中的条件必须全部满足，多条规则之间构成“或”关系。
- 条件支持 HTTP 状态码或范围、响应头存在或相等或正则匹配、JSON 路径存在或相等或正则匹配，以及原始错误响应体正则匹配。
- 分类结果支持额度不足、凭证无效、成功和无结论。
- 没有规则命中时，合法 `2xx` 响应默认为成功，其他响应默认为无结论。
- TUI 提供规则表单和使用粘贴响应样例进行测试的能力。

## 本地端点

- 所有路由池共用一个本地监听地址和端口。
- 每个路由池拥有用户设置且全局唯一的稳定名称，并以 `/pools/{name}` 作为本地 Base URL 路径前缀。
- 请求方在池前缀后追加上游请求路径；路由器去掉池前缀后，将剩余路径拼接到服务配置的上游基础地址。
- 第一版只监听回环地址，默认使用 `127.0.0.1:8787`；用户可以修改端口，但不能绑定外部网卡地址。
- 第一版不提供局域网、容器跨网络或远程访问，也不要求本地请求方提供额外的入站 API Token。

## 平台范围

- Linux 是第一版正式支持和端到端验证的平台。
- macOS 保持可用，但不要求与 Linux 相同深度的自动化验证。
- Windows 只要求能够交叉编译，第一版不承诺运行行为。

## 凭证存储

- 第一版使用独立的本地凭证文件明文保存 API Key，不实现加密凭证库或系统密钥环集成。
- Linux 和 macOS 上必须以仅当前用户可读写的 `0600` 权限创建并维护凭证文件；权限不安全时拒绝加载并明确报错。
- 日志、错误信息和 TUI 默认只展示凭证名称或脱敏指纹，不得显示完整 API Key。

## 配置体验

- 所有日常配置操作都必须能在 TUI 中完成，包括服务配置和路由池的增删改、凭证增删改与排序、手动切换、状态操作、立即验证及全局设置。
- TUI 提供实时日志查看和筛选。
- 配置文件保持人类可读，但只在启动时加载；第一版不检测或热重载运行期间的外部修改。
- TUI 保存配置时必须使用原子写入，避免中断导致配置损坏。
- 首次启动进入配置向导；至少创建一个路由池和一个凭证后才启动代理。

## 凭证状态

- **未知**：新凭证尚未验证。立即验证一次，不参与定期验证。
- **可用**：凭证可以接收请求，不做定期验证。
- **额度不足**：凭证不参与路由，按计划定期验证。
- **凭证无效**：认证或配置有误，等待用户修改或手动重验。
- **已禁用**：用户主动将凭证排除，只有用户可以恢复。
- 超时、服务端错误和瞬时限速等请求故障不改变凭证的持久状态。

## 透明重试

- 只有明确命中额度规则或认证失败规则，且尚未向请求方发送响应头或响应字节时，才切换凭证并重放原请求。
- 响应一旦对请求方可见，就不得重试；若之后识别到额度不足，仍可更新凭证状态。
- 同一次请求对每个候选凭证最多尝试一次，防止循环。
- 瞬时故障默认不触发切换或重试。
- 明确认证失败时将凭证标记为凭证无效；该状态不参与定期验证，只能通过修改凭证或手动重验恢复。

## 路由选择

- 每个路由池维护一个当前凭证，所有正常请求持续使用该凭证，不做轮询或负载均衡。
- 当前凭证额度不足时，按用户可调整的池顺序循环查找下一个可用凭证，并将其设为当前凭证。
- 用户手动选择可用凭证后，该凭证成为当前凭证。
- 并发中的旧请求不迁移；切换只影响后续请求和各请求尚未开始的重试。
- 请求到达时若池内没有可用凭证，但当前凭证处于额度不足，仍使用当前凭证向上游尝试一次，不由路由器合成失败响应，也不切换重试。
- 上述真实请求成功时，将当前凭证恢复为可用；仍命中额度规则时，保持额度不足。两种情况下都将上游响应原样返回请求方。
- 未知、凭证无效和已禁用的凭证不得作为最后尝试目标；如果池内只剩这些状态，则不发送上游请求并返回本地错误。

## 会话间状态

- 凭证状态、当前凭证、最后状态变化时间与原因、下次额度验证时间必须跨 TUI 会话持久化。
- TUI 关闭期间不执行额度验证。
- TUI 启动时，已经到达验证时间的凭证立即进入验证队列；尚未到期的凭证继续保持额度不足。

## 额度验证调度

- 只对额度不足状态的凭证执行定期验证。
- 各路由池使用固定验证间隔，默认五分钟，并允许用户配置。
- 验证调度不读取或依赖上游响应中的恢复时间，也不做退避。
- 用户可以随时手动触发验证。

### 验证结果

- 符合协议的成功响应将凭证状态改为可用。
- 明确命中额度规则的响应使凭证保持额度不足。
- 明确命中认证失败规则的响应将凭证状态改为凭证无效。
- 超时、服务端错误、瞬时限速等无结论故障不改变状态，并记录日志。
- 未知凭证首次验证得到无结论结果后保持未知，只允许用户手动重验，不参与真实请求或定期验证。
