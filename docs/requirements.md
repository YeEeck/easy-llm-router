# 产品需求

本文只记录访谈中已经确认的产品需求；未决事项在确认后再加入。

## 已确认需求

- 产品以本地透明反向代理的形式接收请求，并由同一进程中的 TUI 管理；退出 TUI 即停止代理。
- 路由和可用状态绑定到上游凭证。第一版不识别多个 Key 背后的共享账号或额度。
- 路由池只包含协议和模型名兼容的上游凭证。请求与响应保持协议透传，不做协议转换或模型映射。
- 只有响应明确命中服务的额度规则时，才将上游凭证标记为额度不足。瞬时限速、认证失败、超时和服务故障必须区别处理。
- 用户可以手动切换当前上游凭证，也可以手动将上游凭证标记为额度不足。
- 日志必须能够还原凭证选择、响应分类、切换重试和额度验证的决策链。默认不得记录 API Key、认证头或请求正文。

## 凭证状态

- **未知**：新凭证尚未验证。立即验证一次，不参与定期验证。
- **可用**：凭证可以接收请求，不做定期验证。
- **额度不足**：凭证不参与路由，按计划定期验证。
- **凭证无效**：认证或配置有误，等待用户修改或手动重验。
- **已禁用**：用户主动将凭证排除，只有用户可以恢复。
- 超时、服务端错误和瞬时限速等请求故障不改变凭证的持久状态。

## 透明重试

- 只有明确命中额度规则，且尚未向请求方发送响应头或响应字节时，才切换凭证并重放原请求。
- 响应一旦对请求方可见，就不得重试；若之后识别到额度不足，仍可更新凭证状态。
- 同一次请求对每个候选凭证最多尝试一次，防止循环。
- 瞬时故障默认不触发切换或重试。
